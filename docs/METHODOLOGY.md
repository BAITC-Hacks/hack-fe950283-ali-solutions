# Методика и ограничения

## Наблюдение

Depth — глубина обнаружения. На depth=4 исходящие не наблюдаются. Seed имеют неполный вход. Вход и выход относятся только к данной выгрузке; превышение выхода над входом может объясняться внешними поступлениями или начальным остатком.
Набор июля: 2248 узлов, 3119 рёбер, 4840 транзакций, 81 seed; 35 слабых компонент со всеми узлами и 16 без изолятов.

Входные суммы должны быть положительными и конечными; n_tx — положительным целым. Согласование edges/transactions: atol=0.01 KZT, rtol=1e-10. Дубли агрегированных пар отклоняются. Дубли операций без transaction_id не удаляются.
Self-loop сохраняется в исходном графе и обороте, но не добавляет независимого контрагента, не участвует во временном matcher и community projection. Узел только с self-loop попадает в служебную группу без внешних связей.

## Время

Даты сохраняются полностью, включая месяц и год. По каждому узлу FIFO сопоставляет входящие суммы с исходящими через 1–2 календарных дня. Истёкшие остатки исключаются, суммы не используются повторно. Допуск остатка 1e-9 KZT; исходные суммы не округляются.

Основной ratio = matched_eligible / eligible. В eligible входят только поступления с полным двухдневным окном до period_end. Coverage = eligible / весь вход. При отсутствии знаменателя или ненаблюдаемых исходящих ratio недоступен, а не равен нулю.
Same-day = сумма min(дневной вход, дневной выход) по датам, отдельная характеристика совместной активности без утверждения порядка.
Начальный остаток и невидимые операции неизвестны. FIFO отражает совместимость объёмов, а не идентификацию конкретных денег.

Повторяющиеся маршруты — пары контрагентов с активностью через 1–2 дня на нескольких датах; их суммы не атрибутируются.
Структурные циклы ограничены длиной 6 и числом 5000. Временная совместимость требует строго возрастающих полных дат хотя бы при одной ротации цикла. Она не доказывает возврат тех же денег. Достижение лимита видно в manifest и UI.

## Роли

Сохранён порядок: coordinator → consolidator → distributor → transit → terminal → peripheral. Основная — первая выполненная; остальные сохраняются отдельно.

- Coordinator: >=5 плательщиков, >=10 получателей, >=5 связей с ключевыми узлами.
- Consolidator: >=4 плательщиков либо >=3, из которых >=2 seed; сбор доминирует. Сохранено правило для хабов.
- Distributor: >=10 получателей и получателей >=3 × плательщиков; сохранено дополнительное правило доминирующей раздачи у хаба.
- Transit: не seed, depth<4, положительный выход; out/in 0.8..1.2 либо временная совместимость >=0.6 при out/in 0.5..2.0; минимум входа/выхода >=20000 KZT.
- Terminal: не seed, depth<4, есть вход и наблюдаемый выход <=10% входа; вход >=100000 KZT, либо >=2 плательщика, либо >=3 поступления. Это кандидат в пределах наблюдения, не подтверждённый конечный получатель.
- Peripheral: остальных порогов не достигнуто. Для изолятов role_score=0.

Role score = 0.5 + 0.5 × исходная сила признака для сработавшей непериферийной роли. Используется сохранённое логарифмическое насыщение sat(x,lo,hi)=clip(log(x/lo)/log(hi/lo),0,1).
Для периферии — прежняя эвристика расстояния от порогов, у границы уменьшенная вдвое, у изолятов ноль. Scores не калиброваны и не являются вероятностями. Полные формулы силы признака находятся в roles.assign; пороги — config.py.

Диагностическая логистическая регрессия прогнозирует наличие наблюдаемых исходящих по входным признакам глубин 1–3. Для 5-fold CV нужно >=5 узлов каждого класса. AUC относится к этой наблюдаемой цели, не к точности ролей; перенос на depth=4 не валидирован. Ошибка/отсутствие sklearn возвращает unavailable. Модель не влияет на назначение роли или priority.

## Приоритет и структура

Сохранены веса: роль 0.30, связь с seed 0.20, объём 0.20, положение в сети 0.15, паттерны 0.15.
Компонента seed содержит достижимость и существующую модель пропорционального смешивания. Достижимость считается по направленным путям длиной 1..4, без пути seed к себе.
Атрибуция смешивания предполагает доступный объём max(вход,выход) и полную маркировку исходящих seed; это выбранный сценарий, не наблюдаемый остаток или доказанная сумма доставки.

Priority = сумма(weight × component) × seed_factor / normalizer; seed_factor=0.85 для seed и 1 для остальных; normalizer — максимум скорректированной суммы. При нулевом максимуме используется 1. Изоляты имеют нулевые компоненты. Итог округляется до 4 знаков, равенство разрешается gid ASC. Все множители доступны в CSV и карточке.

PageRank — направленный, вес sum_kzt; betweenness — точный направленный без весового расстояния. Louvain — неориентированная проекция, как прежде: встречные log1p(sum_kzt/5000) суммируются. Схема весов не заменялась на формулу из архива.
Изоляты объединены в явно служебную категорию 0 «нет данных», а не связанное сообщество. Внутренний оборот кластера считает каждое исходное направленное ребро один раз.
Устойчивость кластеров — Jaccard по 10 перезапускам, не гарантия неизменной структуры. Симуляция исключения узлов показывает свойства наблюдаемого графа без адаптации участников.

## AI и интерпретация

Числа/роли определяет ядро. UI и AI используют AnalysisService. Проверяются ссылки на серверные факты и существование gid, но свободное объяснение LLM не становится доказательством только из-за корректных ссылок.
Ошибки/невалидный ответ вызывают локальный fallback. Бюджеты: 3 раунда, 6 tools, 60 секунд, 20 секунд на HTTP, ответ провайдера <=256 KiB, контекст <=120000 байт. Списки tool output ограничиваются до сериализации, JSON не обрезается.
