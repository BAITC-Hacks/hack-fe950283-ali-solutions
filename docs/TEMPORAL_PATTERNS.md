# Временные и структурные признаки

Все признаки рассчитаны только по наблюдаемым переводам. Внутри дня время операции неизвестно; совпадение даты не задаёт порядок. Петли `src=dst` исключены из временных признаков. Ни один признак сам по себе не означает нарушение или виновность.

## Входящий всплеск

Пусть `D` — число календарных дней от самой ранней даты наблюдаемых переводов до конца периода включительно, `N` — число входящих операций узла за это окно, `P` — максимальное число входящих операций за один день. Дни без операций включаются в знаменатель.

- Среднее число операций в день: `N / D`.
- Отношение пика к среднему: `P / (N / D)`; при отсутствии поступлений отношение не определено.
- Признак всплеска: `D >= 3`, `P >= 3` и отношение `>= 3` одновременно.
- При нескольких равных пиках показывается самая ранняя дата.

Пороги находятся в `moneygraph/config.py`: `BURST_MIN_DAYS`, `BURST_MIN_TX`, `BURST_MIN_RATIO`. Это описательный показатель концентрации активности внутри доступного окна. Он не оценивает значимость статистически, не учитывает привычный профиль за предыдущие месяцы и **не меняет роль или приоритет**. Низкая активность в остальные дни способна повысить отношение; аналитик видит числитель, среднее и длительность окна.

В `nodes_roles.csv` и `get_node_report(...).result.temporal`:

| Поле | Смысл |
|---|---|
| `burst_in_max_tx` | Максимум входящих операций в день |
| `burst_in_day` | Дата этого максимума |
| `burst_in_mean_daily_tx` | Среднее с учётом дней без операций |
| `burst_in_ratio` | Максимум / среднее |
| `burst_observation_days` | Календарная длина наблюдаемого окна |
| `burst_in_flag` | Выполнены все три порога |

Период начинается с минимальной наблюдаемой даты набора, а не с первого поступления конкретного узла. Данные до этой даты неизвестны. У seed входящие неполны, поэтому всплеск описывает только видимую часть активности.

## Другие признаки

| Признак | Правило и ограничение |
|---|---|
| `sync_payers_max`, `sync_day` | Максимум разных плательщиков в один день; флаг синхронного сбора при ≥3. Общая дата не доказывает координацию. |
| `fast_in_share` | FIFO-сопоставление поступлений с расходами строго через 1–2 календарных дня, без повторного использования сумм. Знаменатель — только поступления с полным двухдневным окном. |
| `same_day_kzt` | Сумма дневных минимумов входа и выхода; описывает активность, не последовательность переводов. |
| `fast_routes` | Число разных пар A→узел→B, где A≠B и есть входящая/исходящая операция с лагом 1–2 дня. |
| `repeated_routes` | Число таких пар A/B, для которых совместимые переводы найдены на ≥2 разных входящих датах. Это не трассировка конкретных средств. |
| `n_cycles` | Число структурных простых циклов длиной ≤6 через узел, с общим ограничением выдачи 5 000 циклов. |
| `n_return_cycles` | Число этих циклов, у которых хотя бы в одном повороте есть строго возрастающая последовательность дат. Один день не подтверждает возврат. |
| `split_days` | Число пар «получатель + дата» с ≥2 переводами от узла; флаг дробления при ≥3 таких парах. Это счётчик повторных переводов, не доказательство обхода порога. |
| `anomaly_pct`, `anomaly_feature` | Максимальный процентиль степени или оборота среди узлов того же колена; материальный порог защищает от единичных малых операций. |

Поля синхронности, маршрутов, циклов, дробления и аномалии доступны в `get_node_report(...).result.patterns`, справке Markdown и исходном dataframe. Основные временные и структурные счётчики экспортируются в `nodes_roles.csv`.

## Общие получатели в ассистенте

Запрос «кто собирает деньги с этих gid» по умолчанию ищет **прямого получателя всех выбранных источников**. Явный запрос «кто достижим через 3 шага» включает направленную достижимость. Режим «хотя бы от двух» включается только такой формулировкой и маркирует результат `от X из N`.

Поддерживаются 2–20 входных gid, повторённые идентификаторы сворачиваются в уникальные источники; для поиска нужно минимум два разных узла. Неизвестный gid не игнорируется. Глубина ограничена четырьмя рёбрами. Ответ содержит факты, ссылки на них и параметры вызова, а не только свободный текст.
