# Демо MoneyGraph — 5 минут

## Подготовка

Используйте окружение Python 3.12 из README. В корне должны быть data/ с тремя исходными parquet. Остановите прежний сервер на выбранном порту, если он запущен. Внешний ключ не нужен.

Перед выступлением откройте терминал в корне проекта и браузер на [localhost:8765](http://localhost:8765). Не открывайте CSV в редакторе, который преобразует длинные gid в число с плавающей точкой; используйте поиск в интерфейсе.

## Сценарий

| Время | Действие | Что показать / сказать |
|---|---|---|
| 0:00–0:40 | Запустить команду ниже | Из исходных parquet считаются метрики, роли, кластеры, приоритеты и три CSV. В консоли — 14 проверок экспорта и длительность. Сохранённые запуски занимали 24–29 с; это замер на текущем компьютере. |
| 0:40–1:10 | Открыть главную карту и топ | 2 248 узлов, стрелки направления, цвета ролей; три CSV доступны в экспорте. 50 позиций топа имеют причины. |
| 1:10–2:00 | Первый узел топа, окружение и формула | Объяснить coordinator по входным/выходным контрагентам и ключевым связям. Показать полную формулу приоритета и наблюдаемые пути от seed. |
| 2:00–2:45 | Узел transit | Отличить правило пропуска от временного признака. Показать суммы, долю FIFO, знаменатель и покрытие окна. |
| 2:45–3:25 | Узел depth=4 | Нулевой видимый выход не означает terminal: исходящие не выгружены. Модель — только подсказка; следующий запрос — продолжение выгрузки. |
| 3:25–4:15 | Найти произвольный gid жюри; общий получатель нескольких узлов | Открыть связи и кластер; различить «прямой получатель всех» и достижимость через посредников. |
| 4:15–4:45 | Локальный ассистент и экспорт | Запрос «Топ-5 консолидаторов», факты и ссылки; скачать CSV или справку узла. Всё работает без внешнего LLM. |
| 4:45–5:00 | Ограничения и развитие | Гипотезы, неполные входы seed, обрыв depth=4, суммы ниже порога не видны. Для миллиона узлов — серверные подграфы и другой backend. |

Живой запуск (PowerShell):

```powershell
$env:AI_ENABLED="false"
.\.venv\Scripts\python.exe serve.py --port 8765 --no-open
```

serve.py сначала вызывает тот же pipeline, что run.py, публикует проверенный out/, затем запускает локальный сервер. Если нужен только комплект для сдачи, достаточно `.\.venv\Scripts\python.exe run.py`.

## Три примера для разбора

Эти gid выбраны из результата для демонстрации и не зашиты в правила аналитики. Перед выступлением сверяйте показатели с текущим расчётом; место в топе может меняться при изменении методики.

| gid | Содержательный разбор |

| 100000008603629100 | coordinator: 19 плательщиков, 61 получатель, 19 связей с ключевыми узлами. Вход 1 817 300 ₸, выход 4 986 156 ₸. Пороги 5/10/5 пройдены. Выход больше входа допускает внешний вход или начальный остаток. Приоритет не равен сумме пяти компонент без нормализации. |
| 100000006518161100 | transit: не seed, depth=1, 3 плательщика и 2 получателя. Вход 594 200 ₸, выход 595 899 ₸: P≈1.003 попадает в [0.8,1.2]. FIFO-доля ≈34.9%, поэтому роль здесь объясняется коэффициентом пропуска, а не порогом быстрого перечисления 60%. |
| 100000001053894100 | peripheral на depth=4: 7 поступлений на 2 000 000 ₸ от одного плательщика, исходящие не наблюдаются. Временной ratio недоступен; terminal не назначается. Запросить исходящие следующего колена. |

## Три произвольных gid за минуту

Для каждого узла: 5 секунд на поиск полного ID → 10 секунд на роль и числовое evidence → 5 секунд на раскрытие сработавших правил. Сначала называйте I/O и порог, затем ограничение seed/depth, если оно есть. При нескольких правилах основная роль определяется документированным порядком. role_score означает соответствие эвристике, не вероятность и не вывод о виновности.

Если жюри выбирает изолят, корректное объяснение: «Внешних связей нет, содержательная роль не установлена, score и приоритет равны нулю; нужна полная выписка». Это лучше домысла по отсутствующим данным.

## Если проверка затягивается

Для отдельной автоматической приёмки используйте `scripts/verify_acceptance.py --timeout 120`: таймаут помечается как неуспех. Если живой прогон не завершился за отведённое время, покажите сохранённые артефакты и acceptance.json, явно назвав их предыдущим расчётом. Не объявляйте незавершённый запуск успешным.
