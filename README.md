# MoneyGraph — объяснимая аналитика наблюдаемой транзакционной сети

Локальный инструмент для анализа связей, финансовых ролей и приоритета проверки. На входе три parquet, на выходе три обязательных CSV, интерактивный направленный граф, справки и запросы дополнительных данных. Роли — эвристики наблюдаемой сети; они не устанавливают виновность или назначение операций.

## Запуск в текущей папке — PowerShell

Одна команда пересчитывает исходные parquet и публикует проверенный комплект результатов (после установки зависимостей):

~~~powershell
.\.venv\Scripts\python.exe run.py
~~~

Для интерактивных запросов и ассистента запустите локальный сервер. Он также выполняет полный пересчёт перед запуском:

~~~powershell
$env:AI_ENABLED="false"
.\.venv\Scripts\python.exe serve.py --no-open
~~~

Откройте [localhost:8000](http://localhost:8000). Статический out/index.html рассчитан на отдельное открытие: поиск, карточки, граф и экспорт не требуют сервера. Аналитические запросы и ассистент требуют локальный serve.py, но не требуют внешнего API. Отдельной сборки npm и режима dev здесь нет: Python формирует готовый HTML.

Для нового окружения нужен Python 3.12 (проверено на 3.12.14, Windows x64):

~~~powershell
python -m venv .venv
# Полное проверенное окружение, включая тесты:
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
# Один запуск от parquet до всех трёх обязательных CSV:
.\.venv\Scripts\python.exe run.py
~~~

Минимальное окружение можно установить из requirements.txt; requirements-ml.txt добавляет необязательную диагностику границы. В Linux аналогичные команды используют .venv/bin/python. Первичная установка требует сети либо заранее подготовленных пакетов; расчёт, просмотр и локальные запросы работают без внешних сервисов.

В новом изолированном venv на текущем Windows проверены зависимости, импорты и полный расчёт за **28.6 с**. Начальная установка была остановлена по лимиту 90 с, но успела установить все требуемые пакеты; повторная установка для этого окружения не потребовалась. Подробности — [CLEAN_INSTALL_CHECK.json](docs/CLEAN_INSTALL_CHECK.json). Linux и отдельная чистая машина не проверялись.

Параметры:

~~~powershell
.\.venv\Scripts\python.exe run.py --data data --out out --period-end 2026-07-31
.\.venv\Scripts\python.exe serve.py --data data --out out --port 8000 --no-open
.\.venv\Scripts\python.exe -m pytest -q
# Приёмка с таймаутом каждого этапа и двумя независимыми расчётами:
.\.venv\Scripts\python.exe scripts/verify_acceptance.py --timeout 120
~~~

Конец наблюдения по умолчанию — дата последней операции, что явно записывается в manifest. Если известен фактический конец периода, задайте --period-end. Каждый serve.py пересчитывает и проверяет результаты перед запуском.

## Работа в интерфейсе

1. Нажмите «Начать с приоритетных» либо найдите узел по ID в верхней строке (клавиша `/`).
2. Откройте карточку: сначала показаны приоритет, переводы и действия. Формула и все признаки доступны в раскрываемых разделах.
3. «Исследовать связи узла» показывает окружение: один шаг вокруг центрального узла, два–три шага по уровням. «Пути от seed» выделяет наблюдаемые направленные пути.
4. Добавьте несколько узлов к сравнению и откройте «Анализ связей». Прямые получатели и достижимость через посредников — отдельные режимы.
5. Кнопка «Экспорт» открывает три обязательных CSV. Справка отдельного узла скачивается из карточки.

Панель анализа закрывается кнопкой × или Esc. На узких экранах фильтры открываются кнопкой «Фильтры». Цвета и компоновка адаптированы по предоставленному референсу; аналитические правила сохранены.

## Что доступно аналитику

- Полный направленный граф, фильтры, поиск любого полного gid или его части, обзор кластера и схема окружения узла.
- Роль с правилом и альтернативными сработавшими правилами; точная формула приоритета с поправкой seed и нормализацией.
- FIFO-совместимость через 1–2 календарных дня, покрытие окна, отдельная активность одного дня, объяснимые всплески входящих и диаграмма по полным датам. [Формулы временных признаков](docs/TEMPORAL_PATTERNS.md).
- Кнопки «Полная справка», «Пути от seed», «Добавить к сравнению», справка кластера.
- Общие получатели **всех** выбранных источников, отдельно прямые связи и достижимость через посредников. Старый инструмент common_downstream сохраняет смысл «хотя бы от двух, X из N».
- CSV и Markdown-справки для скачивания; подсветка существующих путей на графе.
- Диагностическая модель depth=4, запросы продолжения выгрузки и симуляция исключения узлов из копии графа.

## Критерии ролей и приоритета

Обозначения: **I/O** — число разных внешних плательщиков/получателей; **P** — выход/вход в выгрузке; **H** — хаб с I≥5 и O≥10. Ключевые узлы — хабы и кандидаты в консолидаторы/распределители. Правила проверяются сверху вниз: первое сработавшее даёт основную роль, остальные видны в карточке.

| Роль | Формальное правило |
|---|---|
| coordinator | H и ≥5 прямых связей с другими ключевыми узлами |
| consolidator | ((I≥4 или I≥3 при ≥2 seed-плательщиках) и I≥O) **или** (H и O<2×I) |
| distributor | (O≥10 и O≥3×I) **или** (H и O≥2×I) |
| transit | Не seed, depth<4, O>0, минимум входа/выхода ≥20 000 ₸; P∈[0.8,1.2] **или** (FIFO-доля 1–2 дня ≥0.6 и P∈[0.5,2.0]) |
| terminal | Не seed, depth<4, I>0, P≤0.1; вход ≥100 000 ₸ **или** I≥2 **или** ≥3 входящих операций |
| peripheral | Ни одно из предыдущих правил не выполнено; при отсутствии внешних связей role_score=0 |

role_score показывает соответствие эвристике, не вероятность. Для непериферийных ролей это 0.5 + 0.5 × сила признаков, для периферии — расстояние от порогов с поправкой на неполноту. На depth=4 модель остаётся подсказкой и не назначает terminal. FIFO учитывает только входящие с полным двухдневным окном; один день показан отдельно.

Приоритет: (0.30×роль + 0.20×связь с seed + 0.20×объём + 0.15×положение в сети + 0.15×паттерны) × seed_factor / normalizer. Компоненты приведены к [0,1]; seed_factor=0.85 для seed, иначе 1; normalizer — максимальная скорректированная сумма. Изоляты получают 0, равные scores сортируются по gid. Полные формулы силы признаков, ограничений наблюдения, кластеризации и временных паттернов — в [методике](docs/METHODOLOGY.md); исполняемые пороги — в moneygraph/config.py.

### Компактные действия и производительность

Интерфейс использует встроенный Inter и SVG-иконки; подписи кнопок доступны через подсказки. Детали роли, формулы, паттерны и полнота данных раскрываются в карточке. AI-кнопка справа внизу открывает ассистента, Esc сворачивает его без потери истории. Inter и все ресурсы доступны без CDN.

В разделе «Отрисовка» можно включить экономный режим: подпись выбранного узла, прямые линии окружения, мгновенное фокусирование. Он автоматически выбирается для устройств с ≤4 логическими CPU или ≤4 ГБ RAM, если браузер сообщает эти значения; ручной выбор сохраняется. Вся сеть остаётся доступной. Плавные переходы UI учитывают системное уменьшение анимации. [Изменения отрисовки и ограничения замеров](docs/VIEWER_PERFORMANCE.md).

[Всплески и маршруты](docs/TEMPORAL_PATTERNS.md) отображаются в «Паттернах активности» и справке узла. Новые показатели не меняют роли и приоритеты.

## AI

Без ключа доступны аналитические запросы и шаблонный ассистент. Внешний LLM вызывается только при вопросе пользователя и включённой конфигурации:

~~~powershell
$env:AI_ENABLED="true"
$env:OPENAI_API_KEY="<ваш ключ>"
$env:OPENAI_MODEL="<модель вашего API с tool calling>"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
.\.venv\Scripts\python.exe serve.py
~~~

Сохранён совместимый fallback имени модели gpt-5.4; явный OPENAI_MODEL предпочтителен. .env.example — образец; автоматическое чтение .env не реализовано. Ключ остаётся на сервере, не попадает в HTML, CSV или журнал интерфейса.

Ассистент использует allowlist функций, до 3 раундов / 6 вызовов / 60 секунд, до 20 секунд на сетевой запрос. Модель получает ограниченные результаты запросов, а не исходные parquet целиком. При внешнем endpoint эти результаты отправляются его провайдеру; локальность зависит от выбранного OPENAI_BASE_URL.

Ответ содержит проверенные fact IDs и gid; числовые факты показываются из функций. Проверка ссылок не доказывает истинность свободного текста модели. При ошибках — локальный fallback. Реальный цикл проверен с mock-сервером; внешний API в этой итерации не проверялся.

## Проверка и изменения результатов

[Карта проверок](docs/JUDGING_CHECKLIST.md) и [сравнение до/после](docs/CHANGE_IMPACT.md) содержат фактические результаты, ограничения и команды.

Основные изменения: отсутствие terminal на depth=4, отсутствие transit/terminal у seed по неполному входу, нулевые scores изолятов, корректное временное окно и проверяемые запросы. Архитектура, основной словарь ролей и веса приоритета сохранены.

## Архитектура и развитие

![Схема решения](docs/scheme.svg)

parquet → валидация → направленный граф → признаки → роли → приоритет → кластеры → проверенный комплект артефактов → AnalysisService → UI / AI.

При масштабе около миллиона узлов нужны батчевые агрегации, более компактный graph backend, приближённая центральность, ограниченные обходы и серверная выдача подграфов. Это план развития; работа на таком объёме не проверялась.
