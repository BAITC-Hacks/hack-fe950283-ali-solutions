# MoneyGraph — объяснимая аналитика наблюдаемой транзакционной сети

Локальный инструмент для анализа связей, финансовых ролей и приоритета проверки. На входе три parquet, на выходе три обязательных CSV, интерактивный направленный граф, справки и запросы дополнительных данных. Роли — эвристики наблюдаемой сети; они не устанавливают виновность или назначение операций.

## Запуск в текущей папке — PowerShell

Окружение .venv уже подготовлено:

~~~powershell
.\.venv\Scripts\python.exe run.py
$env:AI_ENABLED="false"
.\.venv\Scripts\python.exe serve.py --no-open
~~~

Откройте http://localhost:8000. Статический out/index.html открывается отдельно: поиск, карточки, граф и экспорт работают без сервера. Вкладка «Запросы» и ассистент требуют локальный serve.py, но не требуют внешнего API.

Для нового окружения нужен Python 3.12 (проверено на 3.12.14, Windows x64):

~~~powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
# Необязательная диагностическая модель границы:
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
# Полное проверенное окружение, включая тесты:
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
~~~

В Linux аналогичные команды используют .venv/bin/python. Linux в этой итерации не проверялся. Первичная установка требует сети; расчёт и просмотр — нет.

Параметры:

~~~powershell
.\.venv\Scripts\python.exe run.py --data data --out out --period-end 2026-07-31
.\.venv\Scripts\python.exe serve.py --data data --out out --port 8000 --no-open
.\.venv\Scripts\python.exe -m pytest -q
~~~

Конец наблюдения по умолчанию — дата последней операции, что явно записывается в manifest. Если известен фактический конец периода, задайте --period-end. Каждый serve.py пересчитывает и проверяет результаты перед запуском.

## Что доступно аналитику

- Полный направленный граф, фильтры, поиск любого полного gid или его части, обзор кластера и схема окружения узла.
- Роль с правилом и альтернативными сработавшими правилами; точная формула приоритета с поправкой seed и нормализацией.
- FIFO-совместимость через 1–2 календарных дня, покрытие окна, отдельная активность одного дня и диаграмма по полным датам.
- Кнопки «Полная справка», «Пути от seed», «Добавить к сравнению», справка кластера.
- Общие получатели **всех** выбранных источников, отдельно прямые связи и достижимость через посредников. Старый инструмент common_downstream сохраняет смысл «хотя бы от двух, X из N».
- CSV и Markdown-справки для скачивания; подсветка существующих путей на графе.
- Диагностическая модель depth=4, запросы продолжения выгрузки и симуляция исключения узлов из копии графа.

## AI

Без ключа доступны аналитические запросы и шаблонный ассистент. Внешний LLM вызывается только при вопросе пользователя и включённой конфигурации:

~~~powershell
$env:AI_ENABLED="true"
$env:OPENAI_API_KEY="<ваш ключ>"
$env:OPENAI_MODEL="<модель вашего API с tool calling>"
$env:OPENAI_BASE_URL="https://api.openai.com/v1"
.\.venv\Scripts\python.exe serve.py
~~~

Сохранён совместимый fallback имени модели gpt-5.4; явный OPENAI_MODEL предпочтителен. .env.example — образец; автоматическое чтение .env не реализовано. Ключ остаётся на сервере, не попадает в HTML, CSV или журнал интерфейса.

Ассистент использует allowlist функций, до 3 раундов / 6 вызовов / 60 секунд, до 20 секунд на сетевой запрос. Модель получает ограниченные результаты запросов, а не исходные parquet целиком. При внешнем endpoint эти результаты отправляются его провайдеру; локальность зависит от выбранного OPENAI_BASE_URL.

Ответ содержит проверенные fact IDs и gid; числовые факты показываются из функций. Проверка ссылок не доказывает истинность свободного текста модели. При ошибках — локальный fallback. Реальный цикл проверен с mock-сервером; внешний API в этой итерации не проверялся.

## Проверка и изменения результатов

[Карта проверок](docs/JUDGING_CHECKLIST.md) и [сравнение до/после](docs/CHANGE_IMPACT.md) содержат фактические результаты, ограничения и команды.

Основные изменения: отсутствие terminal на depth=4, отсутствие transit/terminal у seed по неполному входу, нулевые scores изолятов, корректное временное окно и проверяемые запросы. Архитектура, основной словарь ролей и веса приоритета сохранены.

## Архитектура и развитие

![Схема решения](docs/scheme.svg)

parquet → валидация → направленный граф → признаки → роли → приоритет → кластеры → проверенный комплект артефактов → AnalysisService → UI / AI.

При масштабе около миллиона узлов нужны батчевые агрегации, более компактный graph backend, приближённая центральность, ограниченные обходы и серверная выдача подграфов. Это план развития; работа на таком объёме не проверялась.
